# 外部 MCP AI 开发标准

版本：v0.1  
归属：平台团队  
状态：草案

## 目的

本文档面向那些使用 AI 编码助手，将论文项目、开源仓库或内部原型改造成 MCP Server 的外部开发团队。

这份文档可以直接发给 AI 助手作为开发约束。

## 核心目标

构建的 MCP Server 必须：
- 符合平台外部接入规范
- 暴露稳定的工具 schema
- 避免把大结果集直接内联返回给编排层
- 便于人工审核
- 便于多团队重复实现与维护

## 给 AI 开发时必须提供的输入

在要求 AI 助手实现或改造 MCP 服务时，至少要一起提供：

1. 原始论文或仓库引用
2. 目标 MCP 工具清单
3. 平台接入规范
4. capability metadata 模板
5. tool manifest 模板
6. skill draft 模板
7. 关于部署、鉴权、超时的约束

不要只对 AI 说“把这个 repo 包成 MCP”，而不给这些边界条件。

## 开发要求

AI 辅助实现出来的 MCP Server 必须：
- 使用结构化 JSON 输入输出
- 保持字段稳定并统一使用 `snake_case`
- 把编排层摘要和完整产物分开
- 对长任务支持分批、分页或异步任务
- 对大结果集返回稳定句柄，例如 `dataset_id`、`resource_id`、`artifact_id`
- 对论文或原仓库中未支持的能力明确说明

## 大产物规则

如果被改造的项目会生成数据集、语料、提示词池或其他大体量结果，AI 辅助实现时绝不能把完整结果直接内联返回给编排层。

必须改成：
- 在工具内部存储或引用该产物
- 返回一个句柄
- 返回一个简短摘要
- 只返回少量预览
- 提供后续拉取或物化该产物的方法

这条是强制要求。

## MCP 封装策略

当把论文项目改造成 MCP 工具时，AI 助手应该：
- 按能力拆成多个具体工具，而不是做一个巨大的 `run_all`
- 一个工具只做一类能力
- 对大规模生成步骤，封装成“返回句柄”的工具
- 为后续拉取、物化、打分、去重、标注等步骤提供可选跟进工具
- 不要把生成、执行、报告全部塞进一个黑盒工具里，除非平台明确要求

## 工具设计检查清单

AI 助手为每个工具都必须定义：
- 工具名称
- 工具用途
- 输入 schema
- 输出 schema
- 超时或分批策略
- 是否有副作用
- 是否需要审核后再进入下游
- 预期的后续工具链

## 输出设计检查清单

AI 助手必须确保每个工具输出：
- 只返回合法 JSON
- 有简短 `summary`
- 顶层字段稳定
- 有明确错误对象
- 不会悄悄丢字段
- 不会一会儿返回完整正文、一会儿返回句柄，行为飘忽不定

如果工具对大结果集采用句柄返回，还必须说明：
- 句柄字段名
- 对应产物类型
- 后续 fetch / materialize 路径
- 预览数量策略

## Skill 编写检查清单

如果该能力域需要提供 skill draft，AI 助手应确保它：
- 短小
- 偏策略
- 聚焦“什么时候用、怎么用”
- 明确说明该工具是否返回句柄而非完整产物

skill draft 不应包含：
- 完整生成数据集
- 所有资源的大量枚举
- 本该写进 schema 或代码注释的实现细节

## 可追溯性要求

AI 辅助实现必须附一份简短实现说明，至少写清：
- 改造自哪篇论文、哪个仓库或哪种算法
- 哪些部分保持原样
- 哪些部分做了简化
- 哪些部分被省略
- 哪些部分为了适配 MCP 做了结构重组

如果论文算法本身不适合通过同步 MCP 工具暴露，也必须明确写出这个限制。

## 人工复核清单

交付前，开发团队必须人工确认：
- 示例请求可真实跑通
- 示例响应与真实输出一致
- schema 与代码实现一致
- 大结果集是句柄式返回，而不是整包正文返回
- 超时与长任务行为有文档
- 危险输出被正确标记 `requires_review`
- 涉及鉴权、存储、序列化的 AI 生成代码有人审过

## 可直接发给 AI 的推荐开发提示词

可以给 AI 助手如下提示词：

```text
请把附带的项目改造成一个 MCP Server。

要求：
1. 必须遵循平台的外部 MCP 接入规范。
2. 所有工具输入输出都必须是结构化 JSON。
3. 所有字段统一使用 snake_case。
4. 按能力拆分成清晰的 MCP 工具，不要做一个巨大的 run_all 工具。
5. 如果项目会生成数据集或提示词池，不要把完整内容直接返回给编排层；请返回 dataset_id 之类的句柄、简短 summary、count、preview，以及 fetch/materialize 路径。
6. 对长耗时操作补充分批或异步任务支持。
7. 回填 tool_manifest.json、capability_metadata.json 和 skill_draft.md，并保证它们和真实实现一致。
8. 附上一份简短实现说明，写明哪些能力来自源项目，哪些地方为了适配 MCP 做了修改。
9. 不要虚构原项目没有的能力；对限制要明确写出。
```

## 交付包要求

使用 AI 辅助开发的提供方，最终应交付：
- 实现代码
- `tool_manifest.json`
- `capability_metadata.json`
- `skill_draft.md`
- 实现说明
- 示例请求与响应
- 简短人工复核清单
